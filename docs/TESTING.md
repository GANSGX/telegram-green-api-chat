# Проверка приложения

## Автоматическая проверка

```sh
npm ci
npm run check
npm run format:check
```

Для серверных интеграционных тестов среда должна разрешать прослушивание loopback-порта. Upstream-запросы подменяются контролируемым транспортом, доступ к реальному GREEN-API не требуется.

## Проверка без аккаунта

1. Откройте демоверсию. Убедитесь, что сверху видна пометка «Демо».
2. Отправьте текст. Появится локальный ответ, статус последовательно изменится.
3. Введите многострочное сообщение через Shift + Enter. Enter отправляет его.
4. Начните черновик, откройте другой диалог и вернитесь. Черновики должны оставаться раздельными.
5. Создайте новый чат с `@username` и произвольным именем. Он должен открыться пустым и появиться в списке.
6. Найдите чат по имени, затем очистите поиск.
7. На мобильном экране откройте чат и вернитесь кнопкой со стрелкой. Поле ввода остаётся доступным, горизонтальной прокрутки нет.
8. Выйдите из демоверсии. Должна открыться форма подключения.

## Проверка с реальным инстансом

1. Авторизуйте Telegram-инстанс GREEN-API и подключите его данными из кабинета.
2. Если входящие события выключены, включите их в интерфейсе и дождитесь готовности.
3. Создайте чат с разрешённым для тестирования получателем по телефону. Затем проверьте поиск по `@username`.
4. Отправьте сообщение и убедитесь, что оно появилось в Telegram получателя.
5. Ответьте из Telegram. Ответ должен попасть в правильный чат без дубля.
6. Проверьте доставку и прочтение. Их доступность зависит от уведомлений Telegram и GREEN-API.
7. Перезагрузите вкладку. Пока серверная сессия действует, подключение и локальная история восстановятся.
8. Выйдите. История в интерфейсе очистится, токен будет удалён из серверной сессии.

## Проверка ошибок

- Неправильный токен должен дать понятную ошибку подключения без самого токена.
- WhatsApp/MAX-инстанс должен быть отклонён как неподходящий тип.
- Неполный номер и неверный username не должны запускать отправку.
- Скрытый номер должен приводить к предложению использовать username.
- Заполненный webhookUrl не должен молча затираться приложением.
- Пустое сообщение и текст длиннее 4096 символов не отправляются.
- При временном обрыве сети переписка остаётся видна, соединение восстанавливается.
- При неопределённом результате отправки видна соответствующая пометка без автоматического повтора.
- Неудачный запрос выхода сохраняет возможность повторить отключение.

## Что проверено в этой реализации

В браузере проверены экран подключения, демопереписка, многострочная отправка, автоматический демоответ, раздельные черновики, создание диалога, поиск и мобильная навигация на ширине 390 px.

Реальный двусторонний обмен с Telegram нужно проверить с действующим инстансом пользователя. Учётные данные и получатель для реальной отправки при разработке не предоставлялись.
