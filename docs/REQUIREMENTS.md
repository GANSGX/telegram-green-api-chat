# Соответствие техническому заданию

Проверка основана на двух скриншотах исходного задания и последующих указаниях пользователя. Задание разрешает Telegram как альтернативу MAX. Пользователь выбрал Telegram и отдельно попросил воссоздать интерфейс по предоставленным скриншотам Telegram, поэтому они заменяют исходный визуальный референс MAX.

Функциональные требования реализованы. Автоматические проверки подтверждают работу с имитацией GREEN-API. Реальная доставка сообщения в Telegram и получение ответа требуют отдельной проверки с действующим инстансом.

Вложения добавлены по последующему прямому указанию пользователя и расширяют пункт 3 исходного ТЗ. Поддерживаются файлы, фото, видео и обычные аудиофайлы до 16 МиБ. Кнопка вложения рабочая. Запись голосовых отменена пользователем, кнопка микрофона отключена. Звонки не реализованы. Интерфейс повторяет предоставленный Telegram-референс, полный функциональный клон Telegram не заявляется.

## Ожидаемый пользовательский сценарий

| Шаг из задания                           | Что реализовано                                                                            | Что осталось проверить с аккаунтом                                       |
| ---------------------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| Ввести `idInstance` и `apiTokenInstance` | Форма подключения передаёт данные серверу. Сервер проверяет тип и состояние инстанса       | Успешное подключение действующего авторизованного Telegram-инстанса      |
| Ввести телефон получателя и создать чат  | Телефон проверяется методом `checkAccount`, полученный `chatId` используется для переписки | Разрешение номера реального получателя с учётом его настроек приватности |
| Написать и отправить текст               | Оптимистическое отображение и вызов GREEN-API `sendMessage`                                | Появление текста в Telegram получателя                                   |
| Получатель отвечает в Telegram           | Реализована обработка входящего текстового уведомления                                     | Получение реального ответа через очередь инстанса                        |
| Увидеть ответ в том же чате              | Событие маршрутизируется по `chatId`, применяется к модели и отображается в React          | Полный проход сценария без дублей в действующем подключении              |

Поле `apiUrl` дополняет обязательные ID и токен, поскольку текущий контракт GREEN-API использует адрес конкретного инстанса. Его нужно скопировать из кабинета. Поиск по `@username` является дополнительным способом выбрать получателя, когда телефон скрыт настройками Telegram. Используется обычный аккаунт через GREEN-API, а не Telegram Bot API.

## Подтверждённые проверки

- Успешно выполнены 87 автоматических тестов в четырёх файлах
- Проверены доменная модель, клиентский HTTP-контракт, нормализация уведомлений и серверные HTTP-маршруты
- Upstream GREEN-API в тестах заменён контролируемой имитацией. Реальные сообщения при этих проверках не отправляются
- Контракты `checkAccount`, `sendMessage` и HTTP-очереди сверены с официальной документацией Telegram GREEN-API. Ссылки приведены в [README](../README.md#источники-контракта)
- Проверены multipart, лимиты размера, кириллица, MIME, безопасные media URL, HTTP Range, параллельное скачивание, входящие файлы и гонка исходящего media-события
- В браузере проверены предпросмотр и отправка синтетических файла и PNG с подписью в демоверсии, отображение вложений на мобильной ширине
- После переработки интерфейса выполнено браузерное сравнение с референсом на размере 1728 × 920

В текущем наборе нет автоматических React-компонентных или браузерных E2E-тестов. Успешные 87 тестов не означают, что подтверждён обмен с реальным Telegram-аккаунтом. Демоверсия также не подтверждает реальную доставку, поскольку генерирует локальные ответы.
