# Telegram Chat

React-приложение для отправки и получения текстовых сообщений и вложений Telegram через GREEN-API. Интерфейс повторяет тёмный Telegram Web из предоставленного образца, с оригинальным фоном Web A и шрифтом Roboto. Можно подключить свой Telegram-инстанс или открыть демоверсию без аккаунта.

## Быстрый запуск

Нужен Node.js 22.12 или новее и npm.

```sh
npm ci
npm run dev
```

Откройте [локальное приложение](http://127.0.0.1:5173). Сервер API стартует на порту 3001. Кнопка «Открыть демоверсию» позволяет проверить интерфейс и имитацию переписки без реальных отправок.

Для запуска готовой сборки

```sh
npm run build
npm start
```

Откройте [собранное приложение](http://127.0.0.1:3001). Один Node.js процесс обслуживает интерфейс и API. Не запускайте dev-сервер и production-сервер одновременно на одном порту.

## Подключение Telegram

1. Создайте именно Telegram-инстанс в [кабинете GREEN-API](https://console.green-api.com) и авторизуйте свой аккаунт Telegram по [официальной инструкции](https://green-api.com/telegram/docs/before-start/).
2. Скопируйте `apiUrl`, `idInstance` и `apiTokenInstance` в форму подключения. Адрес API нужно брать из кабинета своего инстанса. Значение в форме служит примером.
3. Если приложение предложит включить входящие сообщения, нажмите «Включить». Применение настроек GREEN-API и перезапуск инстанса могут занять до пяти минут.
4. Нажмите «Новый чат». Введите международный номер телефона либо `@username`. Имя контакта можно указать отдельно.
5. Отправьте сообщение. Ответ получателя появится в том же диалоге.

Используется обычный аккаунт Telegram через GREEN-API. Токен Telegram-бота для этого приложения не подходит. Бесплатный или платный тариф инстанса и ограничения Telegram определяются провайдером.

Если номер скрыт настройками приватности Telegram, поиск по номеру может не дать результата. Используйте `@username`. Перед отправкой приложение получает числовой `chatId` методом `checkAccount`.

Для HTTP-очереди поле `webhookUrl` должно быть пустым. Приложение не стирает уже настроенный внешний вебхук. Используйте отдельный инстанс либо измените его конфигурацию в кабинете. Другие приложения также не должны параллельно читать `receiveNotification` этого инстанса.

## Возможности

- Подключение с проверкой типа и состояния инстанса
- Поиск получателя по телефону и имени пользователя
- Отправка и получение текста до 4096 символов
- Фото, видео, аудиофайлы и документы до 16 МиБ, подписи до 1024 символов
- Предпросмотр перед отправкой, проигрывание совместимых аудио и видео, скачивание файлов
- Статусы очереди, доставки, прочтения и ошибки
- Несколько диалогов, поиск, счётчики непрочитанных сообщений
- Отдельные черновики для каждого чата
- Enter для отправки, Shift + Enter для новой строки, поддержка IME
- Мобильная навигация, управление с клавиатуры, доступные диалоги
- Явно обозначенная демоверсия с локальными ответами

Галочка после отправки означает, что GREEN-API принял сообщение в очередь. Доставка и прочтение подтверждаются отдельными событиями. При неопределённом результате сетевого запроса приложение не повторяет отправку автоматически, чтобы не создать дубликат.

## Данные и безопасность

Токен передаётся серверу один раз при подключении и остаётся в памяти процесса. Клиент получает случайную сессионную cookie с `HttpOnly` и `SameSite=Strict`. Токен не записывается в localStorage, sessionStorage, исходники или журнал запросов.

История и черновики живого подключения сохраняются в sessionStorage текущей вкладки и разделены по инстансам. При явном выходе они очищаются. Это не облачный архив Telegram. Закрытие вкладки убирает её локальную историю, перезапуск сервера сбрасывает сессии. Демоданные существуют только в памяти страницы.

Сами файлы и временные blob-URL не записываются в браузерную историю. История хранит только метаданные и непрозрачные адреса BFF. Приватные ссылки GREEN-API остаются на сервере и доступны только в текущей сессии. После её завершения старые вложения нужно открыть в Telegram.

Сервер допускает только документированный шаблон HTTPS-хостов GREEN-API, запрещает перенаправления и проверяет Origin и Host. Тела запросов ограничены, ошибки провайдера очищаются от технических деталей. Для размещения за reverse proxy задайте `ALLOWED_ORIGINS` и обеспечьте HTTPS. В текущей версии сервер предназначен прежде всего для локального запуска.

## Проверки

```sh
npm run check
npm run format:check
```

`check` выполняет проверку TypeScript, тесты и production-сборку. Тесты используют локальный HTTP-сервер и имитацию GREEN-API. Реальные сообщения при тестировании не отправляются. CI повторяет эти проверки на Node.js 22.

[Матрица соответствия ТЗ](docs/REQUIREMENTS.md) отдельно указывает реализованное, проверенное тестами и ожидающее проверки с реальным аккаунтом.

Сценарии ручной приёмки описаны в [документе тестирования](docs/TESTING.md), устройство приложения и границы надёжности в [описании архитектуры](docs/ARCHITECTURE.md).

## Структура проекта

```text
src/
  components/       интерфейс и доступные диалоги
  lib/              API-клиент, модель сообщений, история, useMessenger
  App.tsx           композиция приложения
  styles.css        визуальная система и адаптивность
server/
  app.ts            HTTP API, сессии, единый polling, идемпотентность
  green-api.ts      изолированный клиент GREEN-API
  media.ts          приватный реестр вложений, проверка файлов и скачивание
  events.ts         нормализация и дедупликация webhook-событий
  main.ts           локальный запуск и раздача production-сборки
tests/              доменные и контрактные тесты клиента
```

## Конфигурация

Скопируйте `.env.example` в `.env`, только если меняете порты или адреса. Секреты GREEN-API в `.env` не нужны, они вводятся в интерфейсе. `.env` исключён из Git.

| Переменная        | Значение по умолчанию                       | Назначение                       |
| ----------------- | ------------------------------------------- | -------------------------------- |
| `PORT`            | `3001`                                      | Порт API и собранного приложения |
| `HOST`            | `127.0.0.1`                                 | Адрес прослушивания              |
| `ALLOWED_ORIGINS` | localhost и 127.0.0.1 на портах 5173 и 3001 | Разрешённые адреса через запятую |

Если меняете порт API при разработке, измените также `server.proxy` в `vite.config.ts`. Vite использует фиксированный порт 5173 и не переключается на случайный порт, чтобы не нарушать проверку Origin.
